# Plan: make it easy to run your own copy (v2.1)

Owner decisions (2026-09-27): scope A only ("run your own copy", one instance per server; no multi-server bot). Necessary plus recommended tasks, including the arm64 image. Also fold in the nine ` -- ` dash substitutes left in user- and admin-facing strings (not the hyphens in SHiFT codes). Generic code alerts (other games' formats) are out of scope.

Source: architect's scope-A assessment (2026-09-27). Gate after every step: `ruff check . && ruff format --check . && pytest -q` (real exit code). Voice guide in CLAUDE.md applies to all new docs and comments.

## Code tasks (in order)

1. **Configurable User-Agent contact.** Replace the three User-Agent copies (`pipeline/run.py`, `bot/client.py`, `collectors/rss.py`) with one builder driven by a new `NEWSBOT_CONTACT` env var (URL or email). Default: the repo URL plus "contact unset", with a startup warning when unset. Add to `.env.example`. Source-scan test preventing new hardcoded User-Agents. Prod sets `NEWSBOT_CONTACT` at the next deploy.
2. **Prompt subject.** Optional `digest.subject` (default `"video games"`, so the owner's prompt stays byte-identical, pinned by the existing test) used in `SYSTEM_PROMPT` and the "these games" fallback. Needs an owner `/newsbot preview` before merge (CLAUDE.md rule), even though the default output is unchanged.
3. **`--check-sources` CLI flag.** Runs the real collectors only and prints, per source, item counts and the first error line, plus which topics matched how many items. Needs no Anthropic key (Brave only if `web_search` is configured and keyed). Tests for argparse, secrets gating, and output against fixtures.
4. **Minimal starter config.** `config.minimal.yaml`: one topic, three sources, alerts off, clearly commented; a test that it loads via `load_config`.
5. **arm64 image.** CI builds `linux/amd64,linux/arm64` (`docker/setup-qemu-action`); update the ci.yml header comment. Verify both manifests exist after the first main build.
6. **Dashes in visible strings.** Rewrite the nine ` -- ` in user/admin-facing strings (`config.py` error messages, `pipeline/run.py` publish-failure alert, `bot/client.py` admin alerts, `bot/commands.py` `_NOT_A_CODE_MESSAGE`) and update the tests that pin them. Never touch hyphens inside SHiFT codes.

## Docs tasks

7. **`docs/finding-sources.md`.** Recipes: Steam `app_id` and the news API, YouTube `feeds/videos.xml?channel_id=`, Bluesky profile RSS via DID, subreddit `/top/.rss?t=day` (rate limits, datacenter IPs), Discourse group RSS, press feeds; choosing aliases and entities (the "Borderlands"/"D4" lessons generalized); the dedicated-source rule; `search_queries`; Brave free-tier math; verifying with `--check-sources`.
8. **`docs/self-host.md`.** Prerequisites (Docker ≥ 20.10.10, compose v2; amd64 or arm64 image); creating the Discord app (Public Bot off, no privileged intents, invite scopes and permissions, Developer Mode for IDs; set permissions on the bot's role); keys and costs (Anthropic required ~2¢/run; Brave optional; Bluesky app password optional); `config.yaml` (start from `config.minimal.yaml`) and `.env` (incl. `NEWSBOT_CONTACT`); image choice (upstream public image with `TAG` pinned, or a fork's own CI with `GHCR_OWNER`); first run (`--check-sources`, `/newsbot preview`, `/newsbot status`, the catch-up gotcha); a test guild with a second token; one process per token; never `docker compose config` against the real `.env`; backups (generic cron, or edit the systemd units' path and time); updating and rollback; one copy per server. Header note on `docs/deploy.md`: "the maintainer's own Droplet runbook; see self-host.md".
9. **SHiFT alerts note.** README, `config.example.yaml`, and self-host.md say plainly: Borderlands-family code format only, opt-in, what `@everyone` means in your server, `max_pings_per_day: 0` for a quiet start.
10. **Privacy/terms note.** In self-host.md: `site/` is the maintainer's; a private bot doesn't need policy URLs; a fork can copy `site/`, edit it, and enable Pages.
11. **README reframe.** Intro: built for one server's three games, here's how to point it at yours. A "Run your own copy" section linking 7 and 8. Maintainer-only material (Releasing, Droplet) under "Maintainer notes".

## Acceptance

12. **Stranger test.** An agent follows `docs/self-host.md` from a clean clone with no prior context, doing everything that doesn't need Discord's web UI (config from the minimal starter, `--check-sources`, an offline `--dry-run`, compose files, image pull or local build), and reports every gap or confusing step; fix what it finds. The owner then reads the guide and does the Discord parts against the private test guild.
