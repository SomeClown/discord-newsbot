# Plan: lounge welcomes and a daily quote (v2.2.0)

Source of truth: `docs/design.md` §14 (approved 2026-09-29). Branch `feat/lounge`. Gate after every task: `source .venv/bin/activate && ruff check . && ruff format --check . && pytest -q` (check pytest's real exit code). Each code task: `implement`, then `test-engineer` (adversarial tests for that task); `qa` after task 9; then `docs`. Tasks run in order because several share `config.py`, `client.py`, `commands.py` and `permissions.py`. Everything new is documented in the owner's voice (CLAUDE.md "Documentation voice"). Two hard constraints for anyone writing strings in `newsbot/`: `tests/test_dash_rewrite_tripwire.py` fails on `" -- "` in **any** string literal, docstrings included, so describe fortune attributions as "attribution lines" rather than writing out a spaced double dash. `tests/test_mentions_tripwire.py` allows exactly one `everyone=True`, so every new `AllowedMentions` uses literal `everyone=False` or `.none()`.

No new dependencies (discord.py 2.7.1, httpx, APScheduler 3 are already pinned), so `requirements.txt` and `scripts/lock.sh` are untouched.

## 1. Goal and approach

When this ships, the bot posts a welcome the owner wrote in `config.yaml` to the lounge channel for each new human member (after rules screening if the server uses it), plus one fortune-style quote a day at `daily_quote.time`, taken from a local file or an `https://` URL. There's a no-repeat deck keyed by a hash of each quote's normalized text. Everything that goes wrong goes to the admin channel.

The code follows the shape the SHiFT feature set up. `newsbot/lounge/` holds the logic, with no gateway I/O: parsing, the deck, loading, the welcome decision. `repo.py` holds the SQL. `client.py` does the Discord wiring, with `post`/`alert` callables injected into the lounge code the way `SweepDeps` does it, so almost everything tests without a gateway.

Key decisions:
- **Request the Server Members intent only when `lounge.welcome.enabled` is true** (§3 below).
- **Test trigger is an admin slash command, `/newsbot quote-now`, not a CLI flag** (§4 below).
- **Ship the starter `quotes.txt` at the repo root and `COPY` it into the image at `/app/quotes.txt`.** The container's config lives at `/app/config.yaml`, so `source: quotes.txt` works in Docker with no compose change. The owner's own list goes under `/data` or at a URL.

### Resolved design points

**(a) Server Members intent (item 3).** `discord.Intents.default()` plus `intents.members = cfg.lounge.welcome.enabled`. The daily quote needs no privileged intent.
- **Why conditional:**
  - Least privilege.
  - Every existing install and every self-hoster who doesn't use welcomes keeps working with no portal change after upgrading to 2.2.0.
  - The bot only receives member events when it uses them, which keeps the privacy text honest.
  - Rollback stays trivial.
- **Cost of conditional:** turning welcomes on later is a two-step change (portal toggle, then config). The docs put the portal step first.
- **How a missing toggle fails.** discord.py raises `discord.PrivilegedIntentsRequired` from `connect()` (gateway close 4014). That is **after** `setup_hook` has already run: commands synced, scheduler started, `fail_pending_codes` flipped any stuck codes. The exception escapes `bot.run()` in `__main__` as a traceback. The plan catches it in `__main__.main()` and exits 2 with a one-line message naming the portal toggle and the config key. That matches how config errors already behave under the Docker restart loop.
- **Side effect to know about:** on that failed start, codes flipped by `fail_pending_codes` are never reported, because `on_ready` never fires. It's rare and harmless, and noted in Risks.
- **Keep the member cache on.** Leave `chunk_guilds_at_startup` at its default (True whenever `intents.members` is on). discord.py's `parse_guild_member_update` only dispatches `on_member_update` when the member is already cached; otherwise it discards the event (`state.py` ~line 1154). Chunking at startup is what lets a member who joined before a restart still get welcomed when they pass screening afterwards. At about 50 members, chunking costs nothing.

**(b) Welcome flow (item 4).**
- `on_member_join(member)` and `on_member_update(before, after)` both go through one `_maybe_welcome(member, event)`.
- The pure decision lives in `newsbot/lounge/welcome.py`: `welcome_action(...) -> "ignore" | "wait" | "welcome"`. It returns:
  - ignore when the member isn't in `cfg.guild_id`;
  - ignore when the member is a bot;
  - wait when `member.pending`;
  - welcome otherwise.
- `RecentWelcomes.check_and_record(user_id, now)` applies the 24-hour rule. It records *before* sending, so two events arriving close together can't double-post, and a failed welcome isn't retried (§14).
- `on_member_update` only calls `_maybe_welcome` when `before.pending and not after.pending`. Every other member update (nicknames, roles) is ignored.

**What's known about screening and Onboarding (as far as I can tell; the test guild confirms it):**
- Rules screening (Discord's old "Membership Screening", now configured under Onboarding in Community servers) sets `pending=true` on `GUILD_MEMBER_ADD`. It sends `GUILD_MEMBER_UPDATE` with `pending=false` when the member accepts.
- Discord's docs say `pending` is always present in `GUILD_` member events.
- discord.py 2.7.1 updates `Member.pending` in `_update`, so `before`/`after` reflect the change.

**What's unknown:**
- With Onboarding (the questions and default-channels flow) turned on and rules screening off, `GUILD_MEMBER_ADD` probably fires at join while the member is still answering questions, with `pending=false`. The welcome would then post before they finish onboarding.
- Whether `pending` flips before or after onboarding completes when both are on.
- Whether a member who is still onboarding gets notified by a mention in a channel they may not see yet.
- discord.py exposes `member.flags.started_onboarding` and `completed_onboarding`; changes to those arrive as member updates.

**Verification and fallback:**
- Task 6 logs, at INFO, each member event's `pending`, `flags.value` and the decision. It **never logs the user ID or name** (privacy).
- The test-guild checklist runs joins with screening off, screening on, and Onboarding on.
- **Fallback if Onboarding differs:** change only the readiness predicate. Treat `flags.started_onboarding and not flags.completed_onboarding` as "wait", and in `on_member_update` also welcome on the transition to `completed_onboarding` (plus `not pending`). The 24-hour map already stops a double welcome if both transitions arrive.
- **Residual risk of that fallback:** a member who abandons onboarding is never welcomed. That's acceptable, and arguably correct.
- Because the predicate is one pure function, the fallback is a small follow-up task, not a redesign.

**(c) Quotes (item 5).**

*Where "today" comes from.* `local_run_date(datetime.now(UTC), cfg.digest.timezone)` from `pipeline/run.py`, computed in `client.py` and passed into the lounge code as a `date`, so `quotes.py` doesn't import the pipeline.

*Scheduling.*
- `CronTrigger(hour, minute, timezone=digest tz)`, `id="daily-quote"`, `misfire_grace_time=300`, `coalesce=True`, `max_instances=1`. It's added only when `daily_quote.enabled`.
- The job store is in-memory, so a process that's down at 08:00 computes its next run as *tomorrow* on restart. That gives "missed means skipped" for restarts with no code at all.
- The 300-second grace covers event-loop stalls and a sleeping dev Mac. A longer miss is dropped, and APScheduler logs it at WARNING, which `logging_setup` already lets through.
- **There is deliberately no quote catch-up in `on_ready`.**

*Once-a-day guard.* `lounge_state.last_quote_date` (local ISO date) is checked cheaply before loading, then re-checked inside `claim_quote`'s `BEGIN IMMEDIATE`. That guards a restart near posting time, a DST double-fire for times in the 01:00–02:59 window, and a race with `/newsbot quote-now`. An `asyncio.Lock` on `NewsBot` (`_quote_lock`) also serializes the job and the command.

*Loading a file.* Read on every run, so edits take effect with no restart.
- Missing file: failure.
- Over 1 MiB (`stat` first): failure.
- Not UTF-8 (decoded as `utf-8-sig` to drop a BOM): failure.

*Loading a URL.*
- Fetched through the shared `self.http_client`, so the `NEWSBOT_CONTACT` User-Agent comes for free.
- `client.stream("GET", url, timeout=10, follow_redirects=True)`, with the whole fetch wrapped in `asyncio.timeout(10)`. httpx's timeout applies per operation, not to the whole download, so the outer timeout is what makes it a real 10 seconds.
- Stop reading and fail as soon as the body passes 1,048,576 bytes.
- Require status 200, a final `response.url.scheme == "https"` (no downgrade through a redirect), and a `Content-Type` of `text/plain` (any charset). Decode with the declared charset, or UTF-8 if none is declared.
- Requiring `text/plain` narrows §14's "must be text". The reason: `text/html` is almost always the "I pasted the GitHub page, not the raw link" mistake, and the admin message says exactly that. Flagged for the owner (Q5).

*"A good download."* All of the above passed **and** parsing produced at least one usable quote. Only then is it saved as the last good copy. On any failure the last good copy is used, and one admin line says so ("used the saved copy from <date>"). With no saved copy, the day is skipped with one admin line.

*Last good copy.*
- Path: `Path(db_path).parent / f"lounge-quotes-{sha256(url)[:12]}.txt"`. That's `/data/…` in prod and dev containers (the read-write volume; the root filesystem is read-only and `/tmp` is tmpfs, lost on restart) and `./data/…` when run natively.
- Keyed by URL, so changing the URL never serves the old list as the new one's fallback.
- Written atomically (a temp file in the same directory, then `os.replace`). A write failure only logs a warning.

*Parsing.*
- Use `splitlines()`. An entry separator is a line where `line.strip() == "%"`.
- Right-strip each line, then strip each entry. Drop empty entries.
- Drop entries whose *rendered* message is over 2,000 UTF-16 units. That's measured after the header and `esc()`, since escaping adds backslashes.
- Return the quotes plus the dropped count; the dropped count is logged.
- A file with no `%` lines is one entry, per the fortune format. The docs say so.

*The deck.*
- `quote_hash(text)`: NFKC normalize, `casefold()`, collapse all whitespace runs to one space, strip, then sha256 hex (64 chars).
- `choose_quote(quotes, used_hashes, last_hash, rng)`:
  - Dedupe by hash.
  - Candidates are hashes not in `used`.
  - If there are none, it's a reshuffle: candidates are all current hashes except `last_hash`. If that leaves nothing (a one-quote list), post that one quote anyway.
  - Pick `rng.choice(sorted(candidates))` (sorted so a seeded RNG is deterministic in tests).
  - Return `QuotePick(text, hash, reshuffle)`.
- Stale hashes from quotes that were later removed sit harmlessly in the table until the next reshuffle clears it.

*Record, then post.* `claim_quote` records the hash and date in one transaction. On reshuffle it first deletes every row, then inserts the pick. Then the bot posts. If the post fails, the quote stays marked used and the day stays marked done: no repeat, no retry, one admin alert.

*Rendering.* `render_quote_message(text) = f"{QUOTE_HEADER}\n{esc(text)}"`, sent with `AllowedMentions.none()`. Attribution lines are kept as written. The header wording is an owner decision (checkpoint B); implement with a placeholder constant.

**(d) Early trigger (item 6): `/newsbot quote-now`.**

*Why a slash command:* the CLI never talks to Discord (it prints through `PrintPublisher`), so a CLI flag couldn't test posting in the lounge, and posting is exactly what the test-guild check and the broken-source admin message need to exercise. It mirrors `/newsbot run-now`.

*Behavior:*
- It's registered whenever `daily_quote.enabled`, not gated like `test-alert`, because it posts a real quote and pings nobody.
- It's admin-checked with `_check_admin`.
- It runs the exact same `run_daily_quote` path as the scheduled job, under the same lock.
- If today's quote hasn't posted yet, it posts it now and records the date, so the scheduled job skips today. That's what "early" means.
- If today's quote already posted, a `ConfirmView` asks "Today's quote already posted. Post another one?" On confirm it runs with `force=True`.
- **`force` only bypasses the date guard, never the deck.**
- **Every posted quote is recorded as used,** including forced ones. Members saw it, so leaving it unrecorded would break the no-repeat promise from their point of view. The deck stays consistent because recording is the same `claim_quote` transaction either way.
- The admin gets an ephemeral reply: a jump link, or the reason nothing posted.

### Owner checkpoints (none block the code tasks)

**Checkpoint A (start now; answers needed before task 8 and the prod rollout): quote source and where it lives.**
- What this server's lounge quotes should be. Options: owner-written lines; game-flavored lines; public-domain classics.
- Where the list lives. Options:
  - **A secret GitHub gist's `/raw/` URL without a revision hash.** Editable from a browser or phone, versioned by gist history, and the saved copy covers outages. GitHub's CDN may serve an edit up to about 5 minutes late.
  - **A file on the Droplet at `/opt/newsbot/data/quotes.txt`**, configured as `source: /data/quotes.txt` (the container path). It must be readable by uid 10001. It is *not* covered by the nightly backup, which only backs up the database.
- **Licensing:**
  - Game dialogue (Claptrap lines and the like) belongs to its publishers. A private list for this server is the owner's call, but it shouldn't go in the public repo or a public gist.
  - Many attributed "famous quotes" online are misattributed.
  - The classic BSD/Debian `fortune` data files mix public-domain material with song lyrics, modern authors and comics of unclear redistribution status. Don't copy them into the repo.
  - Not legal advice; flagged so the owner decides with eyes open.

**Checkpoint B (before task 9): exact wording.** The quote header (proposed: `**Quote of the day**`) and the owner's welcome text for prod `config.yaml`.

**Checkpoint C (before the test-guild run): does the prod server use Community, Onboarding and/or Rules Screening?** The test guild should mirror prod, which means enabling Community in the test guild if prod has it.

## 2. Steps

### Task 1: Config models, validation, welcome rendering helpers

Files:
- `newsbot/lounge/__init__.py` (new): docstring only. **No imports**: `config.py` will import `newsbot.lounge.welcome`, and `quotes.py` (task 3) imports `bot.format`, which imports `config`. An eager package import would make a cycle.
- `newsbot/lounge/welcome.py` (new, the rendering half only):
  - `ALLOWED_PLACEHOLDERS = frozenset({"member", "server"})`.
  - `_PLACEHOLDER_RE = re.compile(r"\{([^{}]*)\}")`.
  - `unknown_placeholders(template) -> list[str]`. Lone `{` or `}` stay literal; anything in braces that isn't whitelisted is an error, including `{}` and `{ member }`.
  - `render_welcome(template, *, member_mention, server_name) -> str`. Uses a regex `sub` over the whitelist only, **never `str.format`** (which would choke on stray braces and allows attribute access). Right-strips the result.
  - `WORST_CASE_MENTION = "<@" + "9" * 20 + ">"` (a snowflake is at most 20 digits).
  - `WORST_CASE_SERVER = "😀" * 100` (a guild name is at most 100 characters, so at most 200 UTF-16 units).
  - `worst_case_length(template) -> int`, using a local one-line UTF-16 length. It can't import `format.discord_len` because of the cycle; a comment points at it.
  - `{server}` is inserted **unescaped**. Only people with Manage Server can set the server name, which is the same trust level as the welcome text itself. Mentions are pinned by `AllowedMentions` anyway, and not escaping keeps the worst-case bound exact.
- `newsbot/config.py`:
  - `WelcomeCfg(BaseModel, extra="forbid")`: `enabled: bool = False`, `message: str = ""`.
  - `DailyQuoteCfg(BaseModel, extra="forbid")`: `enabled: bool = False`, `time: str = "08:00"` (validator reuses `_TIME_RE`: `"lounge.daily_quote.time {v!r} is not HH:MM (24-hour)"`), `source: str = ""`.
  - `LoungeCfg(BaseModel, extra="forbid")`: `channel_id: int | None = Field(None, gt=0)` with the `_reject_bool_channel_id` before-validator, `welcome: WelcomeCfg = WelcomeCfg()`, `daily_quote: DailyQuoteCfg = DailyQuoteCfg()`.
  - `AppConfig.lounge: LoungeCfg = LoungeCfg()`.
  - Cross-checks in `load_config`, merged into the one `ConfigError`, no dashes:
    - Either feature enabled with no channel: `"lounge.channel_id is required when lounge.welcome.enabled or lounge.daily_quote.enabled is true"`
    - Welcome enabled with a blank message: `"lounge.welcome.message is required when lounge.welcome.enabled is true"`
    - For a non-blank message (checked even when disabled, so a typo can't wait for the day someone flips it on): each unknown placeholder gives `"lounge.welcome.message has an unknown placeholder {x}; only {member} and {server} are supported"`, and an over-long message gives `"lounge.welcome.message can reach N characters once {member} and {server} are filled in; Discord's limit is 2000"`.
    - Daily quote enabled with a blank source: `"lounge.daily_quote.source is required when lounge.daily_quote.enabled is true"`
    - `http://`: `"lounge.daily_quote.source {v!r} uses plain http; only https:// addresses are allowed"`
    - Any other `scheme://`, or `https://` with no host: `"lounge.daily_quote.source {v!r} isn't an https:// address or a file path"`
    - A relative path resolves against `Path(path).absolute().parent`, deliberately not `.resolve()`, so "the directory the config file is in" means what it says. It's stored back as an absolute path string with `model_copy`, as the Bluesky default names are. URLs stay as-is.
    - Path existence is **not** checked at load. A missing file is a run-time "skip the day" (§14).
  - Add `quote_source_is_url(source: str) -> bool`, the one place that decides.
- `tests/fixtures/config_lounge.yaml` (new): the documented example block, both features on.
- `tests/test_config_lounge.py` (new, written test-first).

Tests:
- The block absent means both features off, `channel_id` None, and existing fixtures unchanged.
- Each error above, and all of them together in one `ConfigError`.
- A disabled block with no channel is fine.
- `channel_id: true`, `0` and `-1` are rejected.
- Unknown keys are rejected at each level (`welcom:`, `daily_quote.tiem`).
- `{member}` and `{server}` are accepted, repeated occurrences are fine, and lone braces are literal.
- Length boundaries: a message that's exactly 2000 units at worst case passes; 2001 fails. Include one with 90 `{member}`s.
- `HH:MM` edge cases: `24:00`, `8:00`, `08:60`.
- `https://` passes; `http://`, `ftp://`, `https://` alone, `HTTP://x` and an empty source fail.
- A relative path resolves to the config's directory, not the current directory (use `tmp_path` plus `monkeypatch.chdir`); an absolute path is unchanged.
- `render_welcome` substitution, and `str.format`-style attacks (`{member.__class__}`) rejected at load.
- The default time is 08:00.

### Task 3: `quotes.py`, the pure half (parse, hash, deck, render)

Files: `newsbot/lounge/quotes.py` (new). The module docstring explains the fortune format and the deck-by-text idea (house-style analogy welcome). Imports `esc`, `discord_len` and `_ALERT_CONTENT_LIMIT` from `newsbot.bot.format`; that's fine, since nothing imports `quotes.py` at config time. Contents:

Tests (`tests/test_lounge_quotes.py`):
- Splitting: `%` alone on a line; ` % ` with spaces; `%%` and `% text` are *not* separators.

  - A removed quote's hash is ignored.
  - Duplicates in the file collapse.
  - Exhausting the deck sets `reshuffle=True` and never picks `last_hash`.
  - A one-quote list reshuffles to itself.
  - An empty list returns None.
- Rendering: `@everyone`, `<@123>`, `<@&456>`, `<#789>`, `https://x`, `discord.gg/x` and markdown in a quote all come out inert.

### Task 4: `quotes.py`, the I/O half (load, cache, daily run)

Files, in `newsbot/lounge/quotes.py`:
- `async def load_source(source, *, http, cache_dir) -> LoadedQuotes(quotes, dropped, origin: "file"|"url"|"cache", problem: str | None, cache_date: date | None)`. Behavior as in §1(c). Raises nothing; every failure becomes `problem`. Error text is cut with `first_line(str(exc), 250)` from `newsbot/text.py`.
- `@dataclass QuoteDeps(source, db_path, http, local_day: date, now, post: Callable[[str], Awaitable[int]], alert: Callable[[str], Awaitable[None]], rng: random.Random)`.
- `async def run_daily_quote(deps, *, force=False) -> QuoteOutcome(status: "posted"|"already_posted"|"skipped"|"post_failed", message_id, note)`. Steps:
  1. The date pre-check, unless `force`.
  2. Load.
  3. On no usable quote, one alert: `"newsbot: no lounge quote today. <reason>"`, then `skipped`. A fallback to the saved copy sends one alert and continues.
  4. Read used hashes and state in `asyncio.to_thread`, then choose.
  5. `claim_quote` (a lost race gives `already_posted`).
  6. Post. On any exception, log and alert `"newsbot: couldn't post today's quote in the lounge: <first line>"`, then `post_failed`.

  All SQLite work goes through `asyncio.to_thread` with short-lived connections, matching the existing pattern.

Tests (`tests/test_lounge_quotes_load.py`), using `httpx.MockTransport` as the collector tests do, and `tmp_path`:
- File: missing, over 1 MiB, not UTF-8, and a good file.
- URL:
  - 200 `text/plain` saves the cache; the cache filename is keyed by URL.
  - 404, a timeout, `text/html` (message mentions the raw URL), and a body of 1 MiB + 1 byte all fall back to the cache.
  - A good download that parses to nothing falls back and doesn't overwrite the cache.
  - A redirect to `http://` is rejected.
  - No cache plus a failure gives `skipped` plus one alert.
  - The User-Agent header comes from the injected client.
- `run_daily_quote`:
  - Already posted today does no network work.
  - `force` posts a second quote and records it.
  - The post raising gives one alert, and the day and hash stay recorded.
  - The posted content is `render_quote_message(...)`.
  - A cache write failure (read-only dir) still posts.

### Task 6: Bot wiring (intents, startup error, welcome handlers, quote job)

Files:
- `newsbot/bot/client.py`:
  - `build_intents(cfg) -> discord.Intents`, used in `NewsBot.__init__`.
  - `self._recent_welcomes = RecentWelcomes()`.
  - `self._quote_lock = asyncio.Lock()`.
  - `async on_member_join(member)` and `async on_member_update(before, after)`; the second only acts on the pending true-to-false transition. Both return at once unless `cfg.lounge.welcome.enabled`.
  - `_maybe_welcome(member, event)`:
    - Logs the INFO line `"lounge member event"` with `event`, `pending`, `flags` and `decision`, and **no user ID or name**.
    - Then decides, renders `render_welcome(message, member_mention=member.mention, server_name=member.guild.name)`, resolves the lounge channel (`get_channel`, falling back to `fetch_channel`), and sends with `discord.AllowedMentions(everyone=False, users=[member], roles=False, replied_user=False)`.

  - `schedule_daily_quote(scheduler, cfg, callback) -> Job`: a module-level helper so it can be tested. It builds the `CronTrigger` with `misfire_grace_time=300`, `coalesce=True`, `max_instances=1`, `id="daily-quote"`, and is called in `setup_hook` only when `daily_quote.enabled`.
  - `build_quote_deps()`: its `post` sends to the lounge channel with `AllowedMentions.none()` and returns the message id; `alert=self.alert`; `rng=random.SystemRandom()`.
  - `async run_quote(force: bool) -> QuoteOutcome`: takes `_quote_lock`, then calls `run_daily_quote`.
  - `_quote_job()`: the job boundary. It calls `run_quote(False)`; a crash is logged and alerts `"newsbot: daily quote job crashed: <exc>"`.
  - No change to `_catch_up`: no quote catch-up.
- `newsbot/__main__.py`: wrap `bot.run(...)` in `except discord.PrivilegedIntentsRequired`. Print `"newsbot: lounge.welcome.enabled needs the Server Members intent. ## 3. Data / schema changes

- Migration 004 (`004_lounge.sql`) adds `lounge_quotes_used(quote_hash PK, used_at)` and `lounge_state(key PK, value)`. It's applied automatically at startup by `store/db.py`'s `migrate()` (`PRAGMA user_version` goes from 3 to 4), in its own transaction.

- The last-good-copy cache is a plain file next to the database (`/data/lounge-quotes-<hash>.txt`), not a schema object.
- Config: a new optional top-level `lounge:` block. v2.1.1 ignores unknown top-level keys (`AppConfig` has no `extra` setting), so the block can stay on rollback.

## 4. Risks and open questions (ranked)

1. **Onboarding versus rules screening behaves differently than assumed.** The result is welcomes too early (mid-onboarding) or never. Mitigation: the INFO event logs, the test-guild matrix, and a one-predicate fallback (§1b). **Needs checkpoint C.**
2. **Deploying 2.2.0 with `welcome.enabled` before the portal toggle.** The bot won't connect and the container restart-loops. Mitigation: the clear exit message, the docs putting the portal step first, and the conditional intent (installs without the feature are unaffected). Side effect: `setup_hook` has already run by the time Discord refuses, so SHiFT codes flipped by `fail_pending_codes` on that attempt are never reported to the admin channel. It's rare and accepted; qa should confirm nothing worse happens.
3. **Quote licensing,** for the redistributed starter and the owner's own list. Mitigation: the task 8 content rule and checkpoint A. Human decision.
4. **Docker path confusion.** `source: quotes.txt` means the baked-in starter, not a file next to the host's `config.yaml`. An owner file must be under `/data` (and readable by uid 10001) or a URL. Mitigation: docs, plus an admin message naming the resolved path on a missing file.
5. **Deploying around 08:00 PT skips that day's quote.** This is by design (§14 B). The deploy window becomes: avoid 07:55–08:05 and 09:00–09:15 America/Los_Angeles.
6. **Member cache dependency.** `on_member_update` needs the member cached. That relies on default chunking, which is covered by a test-guild item: a restart between join and rules acceptance.
7. **A raid of mass joins** makes the bot mention every account in the lounge, at Discord's rate limit. Discord's built-in welcome has the same property. There's no cap in §14; noted, not built (YAGNI). The owner can revisit if it ever happens.
8. **`text/plain`-only** may reject a host serving `application/octet-stream`. The admin message says why. **Q5 for the owner:** accept this narrowing of "must be text"?
9. **Welcome failure alerts are per join** (no dedupe). That's fine at this server's join rate, and the startup permission check catches the usual cause.
10. **Escaped quotes lose intentional markdown** (`*emphasis*` shows literally). That's intended by §14 ("untrusted").
11. **During rollout, members get two welcomes** (Discord's and the bot's) until the built-in one is switched off. It's brief and expected.

Other open questions for the owner:
- **Q6:** confirm that `quote-now` posts count as used and set the day. Recommended: yes.
- **Q7:** confirm the conditional intent. Recommended: yes.
- **Q8:** after turning off the built-in welcome, should the server's System Messages Channel move back to the admin channel? §14 says system messages stay in the admin channel, and it was only pointed at the lounge for the interim welcome.

## 5. Testing strategy

- **Unit (implement, test-first):** every task above lists its tests. Pure logic (config, parse, hash, deck, decision, 24h map, rendering) needs no Discord. I/O uses `httpx.MockTransport`, `tmp_path` and fakes for the Discord channel, guild and member, the same approach as `test_permissions.py` and `test_code_alert_poster.py`.
- **Adversarial (`test-engineer`, after each code task):**
  - hostile quotes: every mention and link form, zero-width and bidi characters, 2,000-unit boundaries with astral characters, a `%` inside a line;
  - hostile welcome templates: nested braces, `{member}{member}` at the limit, format-string tricks;
  - URL edge cases: a redirect chain ending on http, a chunked body over the cap, a slow drip past 10 seconds, a charset lie, empty 200;
  - the cache: a corrupt saved copy, an unwritable directory;
  - the deck: many reshuffles in a row never repeat back to back; editing the list between runs; a hash collision is impossible to force, so skip;
  - races: `claim_quote` from two threads, the job plus `quote-now` together;
  - the 24h map at exactly the boundary and under clock skew;
  - intents failure with codes pending;
  - log records scanned for user IDs.
- **Integration:** `run_daily_quote` end to end against a temp database, a file source and a spy `post`. The missed-run skip uses a real `AsyncIOScheduler`.
- **Manual:** the test-guild checklist below.

### Owner test-guild checklist (dev bot, private guild)

Before starting: stop every other dev process (native `Python -m newsbot` **and** `docker ps`). Enable **Server Members Intent** on the *dev* app in the portal. The owner adds a `lounge:` block to `config.dev.yaml` themselves (agents never read that file), with a test `#lounge`, welcome on, `daily_quote.time` two minutes ahead, and `source: quotes.txt`.

1. Welcome on, portal intent **off**: the bot exits 2 with the intent message. Turn the intent on; it starts.
2. Remove Send Messages in `#lounge` and start: one permission alert names the lounge. Restore it.
3. Screening off: join with the alt account. One welcome, mention only, text as written; `@everyone` in the template doesn't ping. Leave and rejoin within 24h: no second welcome.
4. Enable Community plus Rules Screening, then join with a fresh alt: nothing until the rules are accepted, then one welcome. Repeat, restarting the bot between join and accept: still welcomed.
5. Onboarding on (with and without rules screening): record the event log lines and when the welcome posts relative to finishing onboarding. If it posts mid-onboarding and the owner dislikes that, take the §1b fallback as a follow-up task.
6. Scheduled quote posts at the configured time; a restart after that time posts nothing more today.
7. `/newsbot quote-now` on a fresh day posts and the scheduled run skips; a second `quote-now` asks to confirm; Cancel posts nothing.
8. URL source (a gist `/raw/` URL): posts, and `data/lounge-quotes-*.txt` appears. Change it to a bad URL and trigger: posts from the saved copy, plus an admin note. Use a `text/html` URL with no saved copy (new URL): the day is skipped with an admin message mentioning the raw link.
9. Missing file source: skipped, and the admin message names the path.
10. A hostile quote file (`@everyone`, `<@&role>`, a link): renders inert.
11. Rollback drill: the 2.1.1 image with the same dev config and database starts and ignores `lounge:`.

1. Merge after the checklist, qa and docs. Tag `v2.2.0` and **wait for the tag's CI build** (amd64 + arm64).
2. Prepare the quote source per checkpoint A. For a Droplet file: `/opt/newsbot/data/quotes.txt`, readable by uid 10001, `source: /data/quotes.txt`.
3. **Developer Portal, prod app: Bot, Privileged Gateway Intents, Server Members Intent ON.** This must come first.
4. Give the bot role View Channel and Send Messages in `#the-speakeasy-lounge`, and copy its channel id.
5. Edit a copy of prod `config.yaml` with the `lounge:` block, validate it locally with `load_config` (never `docker compose … config` against the real `.env`), then swap it in.
6. Set `TAG=2.2.0` and run `./scripts/deploy.sh` (it takes a backup; migration 004 runs at startup). **Never deploy 09:00–09:15 America/Los_Angeles, and avoid about 07:55–08:05** (quote time).
7. Check: no permission alert; `/newsbot status` healthy; an alt account join shows the bot's welcome (Discord's will also appear this once).
8. **Then** turn off Discord's built-in welcome (Server Settings, System Messages, "Send a random welcome message when someone joins"). Per Q8, point the System Messages Channel back at the admin channel if the owner agrees.
9. The next morning, confirm the 08:00 quote. Update CLAUDE.md status.
10. **Rollback:** `TAG=2.1.1` and deploy; switch the built-in welcome back on (and the System Messages Channel back to the lounge). The `lounge:` block, the database and the portal intent can all stay.
