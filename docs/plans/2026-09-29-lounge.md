# Plan: lounge welcomes and a daily quote (v2.2.0), revised for mixed quote sources

Source of truth: `docs/design.md` §14 (approved 2026-09-29, quote sources revised the same day, commit 247b5ea). Branch `feat/lounge`. This replaces the plan from commit df2e03a. The welcome flow, intents, `/newsbot quote-now`, scheduling, the once-a-day guard, permissions, privacy, versioning and rollout carry over. What changed: quote sourcing (a list of `wikiquote:`/`file:`/`url:` sources, a built-in default list, a Wikiquote fetcher and parser, per-source decks and caches). The starter `quotes.txt` task is gone.

**Gate after every task:** `source .venv/bin/activate && ruff check . && ruff format --check . && pytest -q` (check pytest's real exit code).

**Workflow:** each code task goes to `implement`, then `test-engineer` (adversarial tests for that task). `qa` runs after task 10, then `docs`. Tasks run in order because several share `config.py`, `client.py`, `commands.py` and `permissions.py`. Everything new is documented in the owner's voice (CLAUDE.md "Documentation voice"). Minimize dashes, and never use `--` as one.

**Three tripwires bind anyone writing in `newsbot/`:**
- `tests/test_dash_rewrite_tripwire.py` fails on `" -- "` in any string literal, docstrings included. Describe fortune attributions as "attribution lines" rather than writing out a spaced double dash.
- `tests/test_mentions_tripwire.py` allows exactly one `everyone=True`. Every new `AllowedMentions` uses a literal `everyone=False` or `.none()`, and never `**kwargs`.
- `tests/test_useragent_tripwire.py` fails on the literal text `User-Agent` on **any line** of any `newsbot/` file except `useragent.py`, and that includes comments and docstrings. Write "user agent" in prose. Never set the header by hand: every request goes through the shared `self.http_client`, which already carries `user_agent_headers()`.

**No new dependencies.** Stdlib `html.parser` does the Wikiquote parsing (reasoning in §1(e)). `pyproject.toml` dependencies, `requirements.txt`, `scripts/lock.sh` and the `Dockerfile` are all untouched. The only `pyproject.toml` change is the version bump.

**Quote provenance rule (applies to every agent, every file):** no agent writes, recalls or invents a quote or an attribution anywhere. That covers code, tests, fixtures, docs and config examples.
- Real quote text appears only in fixtures saved verbatim from Wikiquote (task 4).
- Tests may assert strings copied out of those fixture files, never from memory.
- Every other test string is clearly fake synthetic text with fake names (for example "Mabel Quince", "The Teapot Heist").

## 1. Goal and approach

When this ships:
- The bot posts the owner's welcome from `config.yaml` to the lounge channel for each new human member, after rules screening if the server uses it.
- It posts one quote a day at `daily_quote.time`. Each day it picks a source uniformly at random from `daily_quote.sources` (or the built-in default list of Wikiquote pages for U.S. public-domain authors), then draws from that source's own no-repeat deck.
- Wikiquote pages are fetched at most once a week through the MediaWiki Action API. Every source keeps a last good copy next to the database.
- Posts carry the source's attribution and, for Wikiquote, a link to the page.
- Everything that goes wrong goes to the admin channel.

The shape follows the SHiFT feature. `newsbot/lounge/` holds all the logic with no gateway I/O. `repo.py` holds the SQL. `client.py` does the Discord wiring and injects `post`/`alert` callables the way `SweepDeps` does, so nearly everything tests without a gateway.

**One module beyond §14's component list: `newsbot/lounge/daily.py`, the daily run.**
- Why: `sources.py` imports `quotes.py` for the fortune splitter and the `Quote` type. If the run (pick a source, load, claim, post) also lived in `quotes.py`, the two modules would import each other.
- It's a module split, not new scope. The docs task records it in §14.

### Resolved design points

**(a) Server Members intent. Unchanged; owner accepted.**
- `discord.Intents.default()` plus `intents.members = cfg.lounge.welcome.enabled`. The daily quote needs no privileged intent.
- **How a missing portal switch fails:**
  - discord.py raises `discord.PrivilegedIntentsRequired` from `connect()` (gateway close 4014). That happens after `setup_hook` has already run.
  - `__main__.main()` catches it and exits 2 with a one-line message naming the portal switch and the config key.
  - Side effect: codes that `fail_pending_codes` flipped on that failed start are never reported, because `on_ready` never fires. It's rare; see Risks.
- **Keep member chunking on** (the default when `intents.members` is on). `on_member_update` only dispatches for cached members (discord.py `state.py` `parse_guild_member_update`).

**(b) Welcome flow. Unchanged.**
- `on_member_join` and `on_member_update` both go through one `_maybe_welcome(member, event)`.
- The pure predicate is `welcome_action(in_guild, is_bot, pending)`, returning "ignore", "wait" or "welcome".
- `RecentWelcomes.check_and_record` applies the 24-hour rule. It records before sending, so two close events can't double-post and a failed welcome isn't retried.
- `on_member_update` only acts on the `pending` true-to-false transition.

*What's known about screening and Onboarding:*
- Rules screening sets `pending=true` on join and sends a member update with `pending=false` on acceptance.
- discord.py 2.7.1 updates `Member.pending` in `_update`.

*What's unknown:* how Onboarding without rules screening behaves. The welcome may post mid-onboarding.

*Verification and fallback:*
- Task 8 logs each member event at INFO: `pending`, `flags.value` and the decision. It never logs a user ID or name.
- The test guild runs the join matrix.
- **Fallback:** only the readiness predicate changes. It treats `flags.started_onboarding and not flags.completed_onboarding` as "wait" and also welcomes on the `completed_onboarding` transition. The 24-hour map already stops a double welcome.

**(c) Sources, keys and the deck.**

*Config shape.* Each `sources` entry is a one-key mapping, parsed into `QuoteSourceCfg(kind: Literal["wikiquote", "file", "url"], value: str)` with a `key` property:
- `wikiquote:` + the normalized title: strip, underscores to spaces, collapse whitespace runs, uppercase the first character (MediaWiki treats the first letter as case-insensitive). Example: `wikiquote:Oscar Wilde`.
- `file:` + the resolved absolute path. Relative paths resolve against `Path(config_path).absolute().parent`. That's deliberately not `.resolve()`, so "the config file's directory" means what it says.
- `url:` + the URL, stripped, otherwise as given.

*Why this key stays stable across unrelated edits:*
- It depends only on the source's own identity, not its position in the list or anything else in the config.
- Reordering, adding or removing other sources, or changing the time or channel leaves every other deck alone.
- Changing a source's own identity (a new path, a new URL, a new page title) is a new source with a fresh deck and no saved copy. That's the honest reading, and the docs say so.
- A Wikiquote page renamed on-wiki behind a redirect keeps its key, because the key is the configured title.
- The key text goes in the database as is (readable in a pinch, and it matches §14's "source names and hashes"). Cache filenames use `sha256(key)[:16]`.

*Mixing and failover* (`daily.py`):
- `order = rng.sample(sources, len(sources))`: the first pick is uniform, and each source is tried at most once per run.
- For each source in order: load it. If the load yields at least one quote, draw from its deck and stop. Otherwise record why and try the next.
- If every source fails, skip the day with one admin message listing each source's reason.
- **One decision beyond §14's text:** a run that posted, but had a source fail with no saved copy on the way, still sends one admin line naming that source. Otherwise a typo'd page title would fail quietly on one day in N forever. Fallback lines and this line go out together as one admin message per run, after the post.

*The deck:*
- `quote_hash(text)`: NFKC normalize, `casefold()`, collapse all whitespace to single spaces, strip, then sha256 hex. The attribution is not hashed, so a Wikiquote editor tidying a citation doesn't put a quote back in the deck.
- `choose_quote(quotes, used, last_hash, rng)`:
  - Dedupe by hash.
  - Candidates are hashes not in `used`.
  - If there are none, it's a reshuffle: all current hashes except `last_hash`. If that leaves nothing (a one-quote source), use that one quote.
  - Pick `rng.choice(sorted(candidates))`, so a seeded RNG is deterministic in tests.
- `used` and `last_hash` are **per source**: `last_hash` is that source's most recently used hash. That satisfies "a reshuffle can't repeat yesterday's" whenever yesterday came from the same source, and a different source can't repeat it by definition, since a different source's deck can't contain the same key.

*Record, then post.* `claim_quote` records the source key, hash and date in one `BEGIN IMMEDIATE` transaction; on a reshuffle it first deletes that source's rows. Then the bot posts. If the post fails, the quote stays used and the day stays done: one admin alert, no retry.

*Where "today" comes from.* `local_run_date(datetime.now(UTC), cfg.digest.timezone)`, computed in `client.py` and passed in as a `date`.

*Scheduling.* Unchanged:
- `CronTrigger` in `digest.timezone` with `id="daily-quote"`, `misfire_grace_time=300`, `coalesce=True`, `max_instances=1`.
- The job store is in-memory, so a process that's down at the quote time simply skips the day. There's no catch-up in `on_ready`.
- `_quote_lock` serializes the job and `quote-now`.

**(d) Loading, caching and the weekly limit** (`sources.py`).

*Cache location:* `Path(db_path).with_name(Path(db_path).stem + "-lounge-cache")`, one JSON file per source named `<sha256(key)[:16]>.json`.
- **Paths:** prod gets `/data/newsbot-lounge-cache/`; the dev and staging containers get `/data/dev-lounge-cache/`; a native run gets `./data/newsbot-lounge-cache/`.
- **Why per database:** the Droplet's staging container shares `./data` with prod under a different database name. Keeping caches (and their weekly fetch clocks) per database keeps the two environments from quietly steering each other.
- The root filesystem is read-only and `/tmp` is tmpfs, so `/data` is the only durable choice.
- The directory is created on the first write.

*Cache file:* `{"version": 1, "key", "fetched_at", "attempted_at", "body", "title", "revid"}`.
- `body` is the raw text (file/url) or the API's rendered HTML (Wikiquote), so a parser fix in a later release applies to cached pages at once.
- `title` and `revid` are for Wikiquote only.
- Written atomically: a temp file in the same directory, then `os.replace`. A write failure only logs a warning.
- A corrupt or unreadable cache file is treated as absent, with a warning log.

*What "a good load" means:* the fetch or read passed every check **and** parsing produced at least one usable quote. Only then is the cache overwritten.

*Per type:*
- **File:**
  - Read on every run, so edits need no restart.
  - `stat` first: a file over 1 MiB fails. It's decoded as `utf-8-sig`; anything that isn't UTF-8 fails. A missing file fails, and the problem text names the resolved path.
  - Parsed with the fortune splitter.
  - The cache is rewritten only when `body` changed.
- **URL:**
  - `http.stream("GET", url, timeout=10, follow_redirects=True)` inside `asyncio.timeout(10)`. httpx's timeout is per operation; the outer one makes it a real 10 seconds overall.
  - Fail as soon as the body passes 1,048,576 bytes.
  - Require status 200.
  - **Every** URL in `response.history` and the final `response.url` must be `https`, so there's no downgrade anywhere in a redirect chain.
  - `Content-Type` must be `text/plain` (any charset; owner accepted). The `text/html` failure message says "use the raw link".
  - Decode with the declared charset, or UTF-8 if none is declared.
  - Fetched every time the source is picked; no weekly limit (§14 limits only Wikiquote).
- **Wikiquote:**
  - If the cache exists and `now - fetched_at < 7 days`, use it with no network. That's the normal path, not a fallback, and it sends no admin line.
  - Otherwise fetch (§1(e)).
  - On success, save with `fetched_at = attempted_at = now`.
  - On failure with a cache, use the cache, rewrite it with only `attempted_at = now`, and report a fallback. The weekly rule counts attempts, so a failing page is retried at most weekly, not daily.
  - On failure with no cache, the source fails, and the next run that picks it retries. Worst case that's one request per run for that page.

*Result type:* `LoadedSource(quotes: list[Quote], origin: Literal["fresh", "saved-weekly", "fallback"], problem: str | None, saved_on: date | None, title: str | None)`. It never raises; every failure becomes `problem`, cut with `first_line(str(exc), 250)` from `newsbot/text.py`.

*Parsing and CPU:* parsing runs in `asyncio.to_thread`. A large author page can be a megabyte or more of HTML, and the gateway heartbeat shouldn't wait on it.

**(e) Wikiquote: API choice and parsing** (`wikiquote.py`).

*Which API.* The MediaWiki Action API, `action=parse`:
```
GET https://en.wikiquote.org/w/api.php
  action=parse  format=json  formatversion=2  redirects=1
  prop=text|revid|displaytitle
  disableeditsection=1  disablelimitreport=1  disabletoc=1
  page=<title>
```
(sent as an httpx `params` dict).

Why `action=parse` over the REST HTML endpoints (`/api/rest_v1/page/html/…` or `/w/rest.php/v1/page/…/html`):
- It's the long-stable, documented API.
- One request returns the rendered HTML, the revision id and the resolved title after redirects (`redirects=1`, so a renamed page keeps working).
- It reports a missing or invalid page as a structured JSON error (`error.code` of `missingtitle` or `invalidtitle`) rather than an HTML 404 page.
- The markup was checked against live pages on 2026-09-29.
- The Parsoid `<section>` wrappers the REST output offers would save about a dozen lines of heading tracking. That isn't worth pinning to endpoints Wikimedia has been reshuffling.

*Fetch rules:*
- The shared client, so the `NEWSBOT_CONTACT` user agent comes for free. That's what Wikimedia's user agent policy asks for.
- `asyncio.timeout(10)`, `follow_redirects=False` (the API doesn't redirect; any 3xx is a failure), status 200, `Content-Type` `application/json`.
- A 4 MiB body cap. That's larger than the 1 MiB file/url cap on purpose: the pages checked were 123 KB and 209 KB of JSON, but big author pages run much larger.
- On a JSON `error`: `missingtitle` becomes "Wikiquote has no page called X (renamed or deleted?)"; any other code becomes "Wikiquote said <code>: <info>".
- 429 and 5xx are plain failures: use the saved copy, no retry loop.
- `fetch_page(http, title) -> FetchedPage(title, revid, html)`.

*Page structure, observed on the live pages (Oscar Wilde, Casablanca (film), Friendship):*
- Headings are `<div class="mw-heading mw-heading2"><h2 id=…>Text</h2></div>` (likewise h3 and h4). Some sit inside wrapper divs, for example `<div class="disputed-begin-frame …">` around the Disputed heading, so headings are tracked in document order wherever they appear.
- A quote is a `<li>` in a top-level `<ul>`. Its nested `<ul><li>` holds the citation. On author and theme pages that nested line is the source ("Henry Adams, *The Education…* (1907), Ch. VII."; "**Algernon,** Act I"). On film pages it's a note ("Ranked #67 in the AFI list").
- Film dialogue is one `<dl>` per exchange, one `<dd><b>Speaker</b>: line</dd>` per line, with exchanges separated by `<hr>`.
- Citations carry `<sup>` reference markers, `<a class="external autonumber">[1]</a>` links, and `[dead link]` notes in `<sup>`.

*Why stdlib `html.parser`:*
- `requirements.txt` has no HTML parser beyond `feedparser`'s `sgmllib` shim (no bs4, lxml or html5lib).
- MediaWiki's output is balanced, parser-generated markup, not the tag soup that makes bs4 worth its weight.
- The state needed is small: a tag stack, the current heading chain, list depth, and an ignore-subtree depth.
- `newsbot/text.py` already uses `HTMLParser` the same way.
- bs4 would save maybe 40 lines and cost two new pinned packages, a `scripts/lock.sh` run, and a bigger image.

*Parser rules* (`parse_page(title, html) -> ParsedPage(kind, quotes, dropped_long, dropped_unattributed)`):
1. **Ignore subtrees:**
   - these elements: `style`, `script`, `table`, `figure` (image captions are unattributed pull-quotes), `sup`;
   - anything whose class includes `noprint`, `navbox`, `references`, `mw-references-wrap`, `references-small` or `mw-editsection`;
   - `a` with class `autonumber`.
2. **Void elements** (`br`, `hr`, `img`, `wbr`): `br` becomes a newline; `hr` ends a dialogue exchange. End tags pop the stack back to the matching open tag, and an unmatched end tag is ignored, which keeps the parser robust to the odd stray tag.
3. **Nothing before the first h2 counts** (lead paragraph, "See also" lines).
4. **Skipped sections.** A heading at any level whose text, case-insensitive, equals or starts with any of the following skips everything until the next heading at the same or a higher level:
   - `disputed`, `misattributed`, `attributed`
   - `quotes about`, `about `, `said about`
   - `external links`, `see also`, `notes`, `references`, `sources`, `bibliography`, `further reading`
   - `cast`, `taglines`

   **Decision:** "Attributed" is skipped. Those are secondhand reports, and the lounge posts attributions as fact. Recorded for the owner; it's a one-line change if they want them.
5. **Page kind**, decided once per page and logged at INFO:
   - **work** if there's an h2 "Cast" or "Dialogue", or the title ends in a parenthetical containing "film", "TV" or "series";
   - otherwise **theme** if at least three headings are a single letter A–Z;
   - otherwise **author**.

   The test fixtures pin each kind.
6. **Quote text:**
   - A top-level `<li>`'s own text, excluding nested `ul`/`dl`.
   - Collapse spaces and tabs within lines, strip each line, drop blank lines.
   - Stage directions such as `[to Ilsa]` are kept as written.
7. **Citation:** the first nested `<li>`'s text, cleaned the same way, collapsed to one line, capped at 150 characters with "…".
8. **Context headings:** the current h2/h3/h4 texts, minus generic names ("Quotes", "Sourced", "Quotations", "Dialogue").
9. **Attribution by kind** (joined with ", "; every part comes from the page):
   - **author:** page title, then the context headings, then the citation if present. Example: "Oscar Wilde, The Importance of Being Earnest (1895), Algernon, Act I".
   - **theme:** the citation alone. **A quote with no citation is dropped** and counted in `dropped_unattributed`. The page doesn't say who said it, so we don't either.
   - **work, list items:** the context headings (the character), then the page title. The nested note lines are ignored.
   - **work, dialogue:** each top-level `<dl>` is one quote, one `Speaker: line` per `<dd>`. Attribution is the context headings (for example a TV episode heading), then the page title.
   - `<dl>` blocks on author and theme pages ("Full text online", "Quotes reported in…") are ignored.
10. **Length:** a quote whose normalized text is over 400 characters is dropped and counted (`MAX_WIKIQUOTE_CHARS = 400`). Dialogue counts its speaker prefixes.
11. **Link:** `https://en.wikiquote.org/wiki/` + `urllib.parse.quote(title.replace(" ", "_"), safe="()',")`, using the API's resolved title. It's built only from `quote()`, so it's safe to post unescaped inside `<…>`, which also suppresses Discord's link preview.

**(f) Rendering** (`quotes.py`).
```
{QUOTE_HEADER}
{esc(text)}
{ATTRIBUTION_PREFIX}{esc(attribution)}        (when there is one)
{WIKIQUOTE_LINK_LABEL} <{link}>               (Wikiquote quotes only)
```
- Sent with `AllowedMentions.none()`.
- File and URL quotes have no separate attribution: fortune attribution lines stay inside the text, as written.
- `QUOTE_HEADER`, `ATTRIBUTION_PREFIX` and `WIKIQUOTE_LINK_LABEL` are placeholder constants until checkpoint B. Proposed: `**Quote of the day**`, `~ `, `From Wikiquote:`.
- Any quote whose rendered message is over 2,000 UTF-16 units is dropped (measured after `esc()`).

**(g) `/newsbot quote-now`.** Unchanged; owner accepted.
- Admin-checked and registered whenever `daily_quote.enabled`.
- It runs the same `run_daily_quote` under `_quote_lock`.
- On a fresh day it posts and marks the day, so the scheduled run skips. If today's quote already posted, `ConfirmView` asks first and then runs with `force=True`.
- `force` bypasses only the date guard. Every posted quote is recorded as used.
- The admin gets an ephemeral reply.

**(h) The built-in default list** (`default_sources.py`).
- No imports.
- `DEFAULT_WIKIQUOTE_PAGES: tuple[str, ...]` holds §14's examples: "Oscar Wilde", "Mark Twain", "Benjamin Franklin", "William Shakespeare", "Jane Austen", "Edgar Allan Poe", "Marcus Aurelius". The final list is checkpoint A.
- Below it, **commented out**, go the modern examples (for example `# "Fight Club (film)",`). A plain-language comment next to them says, in the owner's voice:
  - Wikiquote hosts limited excerpts of copyrighted works under its own fair-use policy;
  - a bot reposting them every day is a different use, with real copyright risk;
  - turning them on is a deliberate owner decision, not a default;
  - theme pages (like "Friendship") mix public-domain and modern quotes the same way.
- `config.example.yaml` repeats the same examples and note.

## 2. Steps

### Task 1: Config models, validation, default list, welcome rendering helpers

Files:
- **`newsbot/lounge/__init__.py`** (new): docstring only, **no imports**. `config.py` imports `lounge.welcome` and `lounge.default_sources`, and `quotes.py` imports `bot.format`, which imports `config`. An eager package import would make a cycle.
- **`newsbot/lounge/default_sources.py`** (new): as in §1(h). Module docstring in the owner's voice.
- **`newsbot/lounge/welcome.py`** (new; the rendering half):
  - `ALLOWED_PLACEHOLDERS`, `_PLACEHOLDER_RE = re.compile(r"\{([^{}]*)\}")`.
  - `unknown_placeholders(template)`.
  - `render_welcome(template, *, member_mention, server_name)`: a regex `sub` over the whitelist, **never `str.format`**.
  - `WORST_CASE_MENTION = "<@" + "9" * 20 + ">"`, `WORST_CASE_SERVER = "😀" * 100`.
  - `worst_case_length(template)`, with its own one-line UTF-16 length. It can't import `format.discord_len` without a cycle; a comment says so.
  - `{server}` is inserted unescaped: Manage Server is the same trust level as the welcome text itself.
- **`newsbot/config.py`:**
  - `WelcomeCfg(BaseModel, extra="forbid")`: `enabled: bool = False`, `message: str = ""`.
  - `QuoteSourceCfg(BaseModel, frozen=True)`: `kind: Literal["wikiquote", "file", "url"]`, `value: str`, plus a `key` property (§1(c)).
  - `DailyQuoteCfg(BaseModel, extra="forbid")`:
    - `enabled: bool = False`;
    - `time: str = "08:00"`, whose validator reuses `_TIME_RE`: `"lounge.daily_quote.time {v!r} is not HH:MM (24-hour)"`;
    - `sources: list[QuoteSourceCfg] | None = None`, with a `mode="before"` validator that turns each one-key mapping into a `QuoteSourceCfg` and raises one `ValueError` listing every bad entry by index. Messages:
      - not a mapping, or zero or several keys: `"lounge.daily_quote.sources[{i}] must have exactly one of wikiquote, file or url"`, plus `"(found: …)"` when there's more than one;
      - an unknown key: `"lounge.daily_quote.sources[{i}] has an unknown key {k!r}; use wikiquote, file or url"`;
      - a value that isn't a non-blank string: `"lounge.daily_quote.sources[{i}].{kind} must be a non-empty string"`.
  - `LoungeCfg(BaseModel, extra="forbid")`: `channel_id: int | None = Field(None, gt=0)` with `_reject_bool_channel_id`, `welcome`, `daily_quote`. Then `AppConfig.lounge: LoungeCfg = LoungeCfg()`.
  - **Cross-checks in `load_config`** (after the model validates, before `if errors:`), folded into the one `ConfigError`, no dashes. Load a nested YAML `sources: null` the same as omitted.
    - Either feature enabled with no channel: `"lounge.channel_id is required when lounge.welcome.enabled or lounge.daily_quote.enabled is true"`.
    - Welcome enabled with a blank message: `"lounge.welcome.message is required when lounge.welcome.enabled is true"`.
    - For a non-blank message (checked even when disabled, so a typo can't wait for the day someone flips it on): each unknown placeholder, and the worst-case length over 2000, as in the prior plan.
    - `sources == []`: `"lounge.daily_quote.sources is empty; remove it to use the built-in list, or set lounge.daily_quote.enabled to false"`.
    - **wikiquote:** over 255 characters, contains any of `# < > [ ] { } |`, or starts with `http`: `"lounge.daily_quote.sources[{i}].wikiquote {v!r} isn't a page title (use the title, like \"Oscar Wilde\", not a URL)"`.
    - **url:** `http://` gives `"… uses plain http; only https:// addresses are allowed"`; any other scheme, or `https://` with no host, gives `"… isn't an https:// address"`.
    - **file:** resolve a relative path against the config file's directory (`absolute()`, not `resolve()`) and store the absolute string back with `model_copy`. Existence is **not** checked at load; a missing file is a run-time failure.
    - Duplicate keys: `"lounge.daily_quote.sources[{j}] repeats sources[{i}]"`.
    - Shapes are checked even when `daily_quote.enabled` is false.

  - Purely additive: v2.1.1's `migrate()` no-ops at version 4 and never reads the new tables. Retention doesn't touch them. The nightly `.backup` covers them.
- **The cache** is plain files, not schema: `/data/<db-stem>-lounge-cache/<sha256(key)[:16]>.json`. It's not backed up and safe to delete (the next run refetches or rereads). v2.1.1 ignores it.
- **Config:** a new optional top-level `lounge:` block. v2.1.1 ignores unknown top-level keys (`AppConfig` has no `extra` setting), so the block can stay on rollback.
- **Dependencies:** none. `requirements.txt`, `scripts/lock.sh` and the `Dockerfile` are unchanged.

## 4. Risks and open questions (ranked)

1. **Onboarding versus rules screening behaves differently than assumed.** The result is welcomes too early or never. Mitigation: the INFO event logs, the test-guild matrix, and the one-predicate fallback. **Needs checkpoint C.**
2. **Wikiquote layout changes.** The parse is tied to today's MediaWiki markup (`mw-heading` wrappers, list nesting, `<dl>` dialogue). A skin or parser change could yield zero quotes, or wrong context headings.
   - Mitigation: zero quotes counts as a failed load, so the saved copy is used and the admin hears about it. The HTML is cached raw, so a parser fix applies to cached pages at once. Per-load INFO counts make a sudden drop visible.
   - Wrong attributions are the worse failure. The theme-page rule (no citation, no post) and qa's review limit that.
3. **Page-kind misdetection.** For example, an author page with three single-letter headings would be read as a theme page. The result is attributions missing the author's name, never invented ones. The kind is logged per load; the owner can drop or swap a page. The fixture tests pin the three layouts seen live.
4. **A page renamed, deleted or merged.** A rename behind a redirect keeps working (`redirects=1`), and the key stays the configured title. A deleted page gives `missingtitle`: the saved copy is used for as long as it exists, with a weekly admin line; with no copy, another source is used, plus an admin line each time it's picked. Fix: edit `sources` (which resets that page's deck).
5. **Wikimedia rate limits or blocks.** Load is tiny: at most one request per page per week, and at most one request per source per run. A 429 or 5xx falls back to the saved copy.
   - The real exposure is a self-hoster with `NEWSBOT_CONTACT` unset: the user agent then carries only the repo URL, which Wikimedia may treat as generic. `warn_if_contact_unset` already logs at startup; `docs/self-host.md` says to set it.
   - Prod has it set (CLAUDE.md).
6. **Copyright:**
   - "Public-domain author" doesn't guarantee every quote on the page is public domain (posthumous publications, modern translations). Theme pages mix eras.
   - The commented-out modern examples are the owner's deliberate call.
   - The committed fixtures include some Wikiquote text under CC BY-SA 4.0 (credited in each file's header) and a few modern fair-use excerpts inside Oscar Wilde's and Friendship's kept sections. The trimming rule keeps those few.
   - **Checkpoint A.** Not legal advice.
7. **Deploying 2.2.0 with welcomes on before the portal switch.** The container restart-loops with the clear exit message. The side effect of `fail_pending_codes` codes going unreported on that attempt is accepted; qa confirms nothing worse happens.
8. **Docker path confusion.** `file: quotes.txt` resolves to `/app/quotes.txt` inside the read-only image, where nothing exists. The admin message names the resolved path; the docs say to use `/data/...`.
9. **Deploying around the quote time skips that day's quote.** That's by design. The deploy window is: never 09:00–09:15 America/Los_Angeles, and avoid about 07:55–08:05 (or around whatever `daily_quote.time` is).
10. **The member cache dependency** for `on_member_update`. Default chunking handles it, and the test guild checks a restart between join and acceptance.
11. **Mass-join raid:** one mention per join, the same as Discord's built-in welcome. No cap (YAGNI).
12. **Escaped quotes lose intentional markdown.** Intended (§14: quote text is untrusted).
13. **Two welcomes during rollout** until the built-in one is switched off. Brief and expected.
14. **Decisions recorded for owner visibility** (not blocking):
    - "Attributed" sections are skipped;
    - a run that posted still reports a source that failed with no saved copy;
    - caches are per database;
    - changing a source's path, URL or title resets its deck.

## 5. Testing strategy

- **Unit (implement, test-first):** each task lists its tests. Pure logic (config, split, hash, deck, render, parse, kind, welcome decision, 24h map) needs no Discord and no network. I/O uses `httpx.MockTransport`, `tmp_path`, and fakes for channels, guilds and members, in the style of `test_permissions.py` and `test_code_alert_poster.py`.
- **No network, ever, in tests:**
  - Wikiquote and URL tests build their own `httpx.AsyncClient(transport=MockTransport(...))`.
  - The weekly-rule tests use a transport that fails the test if called.
  - No test constructs a client without a mock transport. qa greps for that.
- **Fixtures:** two real, revision-pinned Wikiquote pages (author, theme) and one synthetic film page, as in task 4. Expected strings are copied from the fixtures.
- **Adversarial (`test-engineer`, after each code task):**
  - hostile quotes and attributions (every mention and link form, zero-width and bidi characters, 2,000-unit boundaries with astral characters);
  - hostile welcome templates;
  - hostile source entries (two keys, nested mappings, non-strings, a title full of `|`, a `file:` of `../../etc/passwd`, which is allowed since it's owner config, but check nothing worse than a read failure);
  - URL redirect chains, drips and charset lies;
  - Wikiquote envelopes with a missing `parse`, an HTML `text` of the wrong type, a huge `text`, deeply nested lists, unclosed tags, headings inside tables (ignored);
  - cache corruption and permissions;
  - clock skew around the 7-day rule;
  - many reshuffles in a row never repeating back to back, per source;
  - the `claim_quote` race;
  - the job and `quote-now` together;
  - log records scanned for user IDs;
  - the three tripwires.
- **Integration:** `run_daily_quote` end to end against a temp database, one fixture-backed Wikiquote source (mock transport), one file source, and a spy `post`. The missed-run skip uses a real `AsyncIOScheduler`.
- **Manual:** the checklist below.

### Owner test-guild checklist (dev bot, private guild)

**Before starting:**
- Stop every other dev process: native `Python -m newsbot` **and** `docker ps`.
- Enable **Server Members Intent** on the *dev* app.
- The owner edits `config.dev.yaml` themselves (agents never read it): a `lounge:` block with a test `#lounge`, welcome on, and `daily_quote.time` two minutes ahead. **Leave `sources` out** for the first run, so the default list is exercised.
- Make sure `NEWSBOT_CONTACT` is set for the dev bot.

**Welcomes:**
1. Welcome on, portal intent **off**: the bot exits 2 with the intent message. Turn the intent on; it starts.
2. Remove Send Messages in `#lounge` and start: one permission alert names the lounge. Restore it.
3. Screening off: join with the alt account. One welcome, mention only; `@everyone` in the template doesn't ping. Leave and rejoin within 24h: no second welcome.
4. Community plus rules screening, fresh alt: nothing until the rules are accepted, then one welcome. Repeat with a restart between join and accept: still welcomed.
5. Onboarding on (with and without rules screening): record the event log lines and when the welcome lands. If it posts mid-onboarding and the owner dislikes that, take the fallback as a follow-up task.

**Default-list quotes:**

6. The scheduled quote posts at the configured time: header, quote, attribution, and a working Wikiquote link. The logs show one `lounge source loaded` line (origin `fresh`, kind `author`, counts). A restart after the quote time posts nothing more today.
7. `/newsbot quote-now` on a fresh day posts, and the scheduled run skips. A second `quote-now` asks to confirm; Cancel posts nothing; Confirm posts, and the logs show `saved-weekly` if the same page came up again (no fetch).
8. Read a few attributions against their linked Wikiquote pages: speaker and work match what the page says.

**Configured sources** (set `sources` to one Wikiquote author, one film or theme page if the owner is comfortable, a `file: /data/quotes.txt` with synthetic lines, and a gist `/raw/` URL):

9. Trigger several confirmed `quote-now`s: each source type posts at some point. A film dialogue posts as one quote with one speaker per line.
10. Fallback: after the file source has posted once, rename the file and trigger until that source is picked. It posts from the saved copy, with one admin line.
11. A nonexistent Wikiquote title alongside good sources: a quote still posts from another source, with an admin line naming the bad title.
12. Every source broken (a bad title, a missing file, a `text/html` URL, all new so there are no saved copies): the day is skipped, with **one** admin message listing each reason.
13. A hostile synthetic quote file (`@everyone`, `<@&role>`, a link): renders inert.

**Rollback:**

14. The 2.1.1 image with the same dev config and database starts and ignores `lounge:`.

## 6. Release and rollout (prod)

1. Merge after the checklist, qa and docs. Tag `v2.2.0` and **wait for the tag's CI build** (amd64 + arm64).
2. Settle the source list (checkpoint A): omit `sources` for the default list, or write the owner's list. For a Droplet file: `/opt/newsbot/data/quotes.txt`, readable by uid 10001, `file: /data/quotes.txt`.
3. **Developer Portal, prod app: Bot, Privileged Gateway Intents, Server Members Intent ON.** This must come first.
4. Give the bot role View Channel and Send Messages in `#the-speakeasy-lounge`, and copy its channel id.
5. Edit a copy of prod `config.yaml` with the `lounge:` block. Validate it locally with `load_config` (never `docker compose … config` against the real `.env`), then swap it in.
6. Set `TAG=2.2.0` and run `./scripts/deploy.sh` (it takes a backup; migration 004 runs at startup). **Never deploy 09:00–09:15 America/Los_Angeles, and avoid about 07:55–08:05** (the quote time).
7. Check: no permission alert; `/newsbot status` healthy; an alt join shows the bot's welcome (Discord's will also appear this once).
8. **Then** turn off Discord's built-in welcome (Server Settings, System Messages, "Send a random welcome message when someone joins"). Per checkpoint D, point the System Messages Channel back at the admin channel if the owner agrees.
9. The next morning, confirm the quote and its link. Update the CLAUDE.md status.
10. **Rollback:** `TAG=2.1.1` and deploy; switch the built-in welcome back on (and the System Messages Channel back to the lounge). The `lounge:` block, the database, the cache directory and the portal intent can all stay.

## 8. Out of scope

- A `/newsbot status` lounge line.
- Welcome embeds or images; per-member or role-based welcomes; DM welcomes.
- A raid or join-rate cap; persisting the 24h welcome map.
- Retrying failed welcomes or quote posts; quote catch-up after downtime.
- Per-source weights, per-source schedules, or per-source time windows.
- Wikiquote languages other than English.
- Year-based filtering of quotes on theme pages.
- Including "Attributed" sections.
- Comment syntax in quote files; a one-quote-per-line format.
- A CLI quote flag or a `--check-sources` extension for lounge sources.
- A preview (non-recording) quote command.
- A starter `quotes.txt` (dropped; the default list replaces it).
- Moving the admin alerts.
- Anything for the paused public-app work.
