Privacy Policy

Effective October 1, 2026. Last updated October 4, 2026.

This page exists because Discord asks bots to have one, and I'm nothing if not compliant with forms. The honest summary: this bot reads the gaming news so you don't have to, and it is remarkably uninterested in you. It used to serve one server. It now serves any server that installs it, so this page has grown a section about what it remembers per server.

What it collects about you

Almost nothing, and not for lack of opportunity. The bot doesn't have Discord's "Message Content" permission, so it can't read your messages. It doesn't read your status or what you're playing, and it keeps no list of members anywhere.

One thing is different on one server. The welcome messages (see "Lounge" below) run on a single server, and for that the bot asks Discord for join events, which means it notices when someone joins (and when they accept the server's rules). It keeps its own record of recent welcomes only in memory, for up to 24 hours, so it doesn't welcome the same person twice. Discord's join events are application-wide, so while that is switched on the bot is told about joins in every server it's in; it ignores all of them except the one with welcomes, and Discord's library may hold those members in memory while the bot runs. None of it is written to disk or to the logs, and the bot still doesn't read messages, statuses or activity.

The bot's own log lines carry server ids (so I can tell which server a problem belongs to) and no user ids. If someone without permission tries an admin-only /newsbot command, the log notes the server and the command, not who tried it. The logs rotate themselves out after roughly 30 MB of other, equally riveting entries.

When you run /news recent or /news search, the bot answers you and forgets you. It doesn't keep a record of who searched for what. (Your search for "Palworld lawsuit" is between you and your conscience.)

What it stores about each server

When a server adds the bot, the bot keeps a small record for that server so it knows what to post and where. Specifically:

  • the server's id, its digest time and time zone, and whether it has finished setup;
  • the games the server follows and the id of the channel each one posts to;
  • the id of the server's admin channel, if one was picked;
  • the SHiFT code settings: on or off, the channel id, and the ping choice (nobody, everyone, or a role id);
  • which tier the server is on (free, or one I cover myself);
  • a record of each digest the bot posted (the day, the status, the ids of the messages it sent, a short note if something went wrong, and for the servers with AI summaries, how many tokens the summary used);
  • a record of each SHiFT code it posted there (the code, the message id, whether it pinged);
  • short plain-text notes about problems, such as a channel it couldn't post in (the newest 20 per server, at most 90 days old).

That's channel ids and settings. There are no member names, no member ids, and no message text from anyone.

Lounge

The lounge (a welcome message for new members, and one quote a day) runs on exactly one server, a friend's. If you're not on that server, none of this applies to you. For that server the bot also keeps the channel id, the welcome text the owner wrote, the quote settings and a hash of each quote's text (so a quote isn't repeated until the rest have had a turn). It holds nothing about people.

What it does collect

Public news: posts from game studios' feeds, Steam announcements, gaming news sites, Bluesky, and a web search. It keeps those items, and the AI-written summaries made from them, for 90 days, then deletes them. They're shared by every server, since they're public news and not about any server. It also remembers every SHiFT code it has seen, forever, so it never announces the same one twice. One subreddit, r/Borderlands4, is read only to spot SHiFT codes: its posts are not kept, are never summarized, and never appear in a digest or in a search. A code that was spotted there is remembered like any other, along with the name of the source and a link back to the post, and its alert may include that link. The database gets backed up nightly; backups are kept for a week.

When the bot is removed from a server

Everything in "What it stores about each server" and "Lounge" is deleted right away when the bot is removed from the server, and again at the next startup for any server it finds it has left. The shared public news and the SHiFT code list stay, because they were never about a server.

There is one exception, and I'd rather say it than have you find it. When the bot became a public app, I moved the one server it already served over to the new design, once, and the bot kept a record of that move: that server's id, the ids of the channels it was using, and a few counts (how many games, and so on). That record isn't deleted when the bot is removed, because it's what stops the move from happening twice. It holds no member data. Also, a deleted server's data can sit in the nightly backups for up to a week before the oldest copy rotates out.

Who else sees what

  • Anthropic receives the public news text so Claude can summarize it, and only for the servers I cover myself (the free tier gets plain headlines, with no AI in the loop). No information about you or any server is included, because the bot doesn't send any.
  • Brave Search receives a handful of search phrases a day, like "Borderlands 4 news", for the games those same servers follow. The results are public news and can show up in any server's headlines.
  • The news sources (studio feeds, Steam, Reddit for SHiFT codes only, Bluesky, gaming sites and Wikiquote) get ordinary requests from the bot, identified by a contact address so they can reach me. They learn nothing about any server or member.
  • Discord handles everything the bot posts and every command you run, under Discord's own privacy policy.
  • DigitalOcean hosts the server it all runs on, and GitHub hosts this page.

Nothing is sold, shared for advertising, or used to build a profile of anyone. I couldn't monetize this if I tried, and believe me, I've got the unfinished side projects to prove it.

Your choices

Don't want the bot anywhere near you? Mute its channel, ignore its commands, or ask a server admin to remove it. Removing it deletes that server's record, as above. If you're an admin and want something deleted without removing the bot, or you just have a question, write to me at the address below.

Kids

The bot isn't aimed at anyone under 13, which is also Discord's minimum age.
